# Family_Wellness

Общая панель для всей семьи: учёт спорта, питания и здоровья. Прогресс общий, мотивация строится на баллах, уровнях, достижениях и семейных целях. Взрослые и дети заходят каждый со своего устройства.

Не входит: подключение фитнес-браслетов, подсчёт калорий по базе продуктов, платежи, общение между семьями, медицинские советы.

## Стек

- Next.js 16 (App Router, server actions), React 19, TypeScript
- Tailwind CSS 4
- Prisma 6 + PostgreSQL (в проекте используется Neon)
- Auth.js (next-auth v5, вход по email и паролю, пароли хешируются bcrypt)
- Zod для проверки данных, Vitest для тестов

## Запуск

```bash
npm install
cp .env.example .env        # впишите свои DATABASE_URL и AUTH_SECRET
npx prisma migrate deploy   # применить миграции
npx prisma generate         # сгенерировать клиент Prisma
npm run dev                 # http://localhost:3000
```

В Windows PowerShell запуск `npm` может быть запрещён политикой скриптов. Тогда используйте `npm.cmd`:

```powershell
npm.cmd run dev
```

## Переменные окружения

Шаблон лежит в `.env.example`, реальные значения храните в `.env` (он в `.gitignore`, в репозиторий не попадает).

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | строка подключения к PostgreSQL (для Neon используйте адрес пулера) |
| `AUTH_SECRET` | секрет для подписи сессий; сгенерируйте `npx auth secret` или `openssl rand -base64 32` |
| `AUTH_URL` | адрес сайта, нужен только в продакшене (ваш домен); локально не задавайте |

## Миграции

- `npx prisma migrate dev` — создать и применить миграцию при разработке (меняете `prisma/schema.prisma`).
- `npx prisma migrate deploy` — применить уже существующие миграции (для сервера и облачной БД).
- `npx prisma generate` — пересоздать клиент Prisma после изменения схемы.

## Тесты и сборка

- `npm test` — тесты (Vitest)
- `npm run build` — сборка (заодно проверяет типы)

## Правила

### Баллы

- Активность: 1 балл за каждые 5 минут, не больше 60 баллов за запись.
- Питание: 5 баллов за запись.
- Вода: 1 балл за каждые 250 мл, не больше 8 баллов за запись.
- Здоровье: 5 баллов за запись.
- Суточные лимиты на пользователя: активность 100, питание 20, вода 8, здоровье 5 баллов в день. Сверх лимита запись сохраняется, но баллы за неё не начисляются.
- Удаление записи отзывает её баллы. Освободившийся лимит не пересчитывает уже сохранённые записи.

### Уровни

Уровень = `floor(sqrt(баллы / 50)) + 1`. Для уровня N нужно `50 × (N − 1)²` баллов: 2-й уровень с 50 баллов, 3-й со 200, 5-й с 800.

### Достижения (10)

- Первая запись каждого вида: активность, питание, вода, здоровье.
- Серия записей 3 и 7 дней подряд.
- 100, 500 и 1000 баллов.
- Пятый уровень.

Достижения не отзываются, даже если запись потом удалена.

### Даты записей

Запись можно сделать только за сегодня или вчера. «Сегодня» определяется по часовому поясу пользователя (поле `User.timeZone`). Пояс принимается только как название из списка IANA (например, `Europe/Moscow`) или `UTC`, при регистрации пояс берётся из браузера и сменой не считается, поэтому первая смена после регистрации доступна сразу, а затем не чаще одного раза в 7 дней.

### Права

- Каждый видит записи всей семьи, но добавляет и удаляет только свои.
- Цели создают и удаляют только взрослые; прогресс цели считается по записям всех членов семьи.
- Данные разных семей изолированы: все запросы фильтруются по семье пользователя.

### Лимиты и защита

- Не более 20 целей на семью.
- Не более 50 записей одного типа на пользователя в день.
- Вход: 5 неудачных попыток по одному email за 15 минут блокируют вход на 15 минут (сообщение «Слишком много попыток, попробуйте позже»). Успешный вход сбрасывает счётчик. Сообщение не показывает, существует ли такой email.


## Деплой (Vercel + Neon)

1. Создайте базу в Neon. Выберите регион ближе к пользователям (для России и Европы — Frankfurt): каждый запрос к удалённой базе занимает время, и от региона зависит скорость сохранения записей.
2. Для `DATABASE_URL` используйте адрес пулера (`-pooler` в имени хоста).
3. Импортируйте репозиторий в Vercel и задайте переменные окружения `DATABASE_URL`, `AUTH_SECRET` и `AUTH_URL` (адрес вашего домена, `https://...`).
4. Примените миграции к рабочей базе: `npx prisma migrate deploy` (с `DATABASE_URL` рабочей базы).
5. Команда сборки `npm run build`; клиент Prisma создаётся автоматически скриптом `postinstall` (`prisma generate`) при установке пакетов.

Для работы за прокси включён `trustHost` в настройках Auth.js.

## Известные ограничения

- В списках на страницах показываются только 30 последних записей семьи.
- Записи с 0 баллов (сверх суточного лимита) всё равно считаются в «первые» достижения и серии.
- Лимит в 20 целей проверяется без блокировки: при одновременном создании двумя взрослыми возможна 21-я цель.
- Защита от перебора считается по email, а не по IP. Регистрация защиты от частых запросов не имеет.
- Нет восстановления пароля и подтверждения email.
- Нет интеграционного теста изоляции семей на реальной БД.
- Поведение на телефонах проверено по коду и разметке, полноценный ручной прогон на устройствах ещё не проводился.
