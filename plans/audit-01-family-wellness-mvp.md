# Аудит: этап 1 «Каркас» (plans/01-family-wellness-mvp.md)

## Итог
**Готово с замечаниями.** Каркас соответствует этапу 1: Next.js, Tailwind, Prisma-схема, базовый layout и Vitest на месте. Блокирующих проблем нет. Есть одно замечание средней важности (`.env.example` попадёт под игнор) и несколько мелких.

## Что соответствует цели
- Next.js App Router и TypeScript: есть `src/app/layout.tsx`, `src/app/page.tsx`, `next.config.ts` и `tsconfig.json` со `strict`.
- Tailwind v4 подключён через `@tailwindcss/postcss`, `globals.css` и `postcss.config.mjs`. Layout адаптивный: контейнер `max-w-4xl`, отступы `px-4`, заголовок `sm:text-4xl`, `lang="ru"`.
- Prisma + PostgreSQL: `prisma/schema.prisma` содержит все модели из плана: Family, User, ActivityLog, MealLog, WaterLog, HealthLog, PointsEvent, Achievement, UserAchievement, FamilyGoal. Есть enum Role (adult/child) и уникальный `Family.inviteCode`.
- Пароли хранятся как `passwordHash`, открытого пароля в схеме нет. Связи идут через `familyId`, что даёт основу для изоляции данных по семье.
- Индексы и каскадное удаление заданы. `UserAchievement` уникален по паре (userId, achievementId).
- Vitest настроен, скрипты `test`, `build`, `dev` и `db:*` есть. README описывает запуск.
- Секретов в репозитории нет. `.env` отсутствует. В `.env.example` только плейсхолдер `postgres:password@localhost`. Я искал слова password/secret/key по файлам проекта, реальных значений не нашёл.
- Лишних файлов нет. Код геймификации, аутентификации и API не писали, это этапы 2–5.

## Замечания (по важности)
1. **Средняя.** В `.gitignore` строка `.env.*` игнорирует `.env.example`. Критичный файл из плана не попадёт в коммит, и тест `.env.example существует` пройдёт только локально. Нужно добавить `!.env.example` после `.env.*`.
2. **Средняя.** Миграций Prisma нет (`prisma/migrations` отсутствует), потому что нет БД. README просит выполнить `prisma migrate dev`, это допустимо. Но первую миграцию нужно создать и закоммитить до этапа 2. Схема тоже ни разу не проверена командами `prisma validate` и `prisma generate`. Тесты проверяют её только регулярками по тексту. Сборка проходит, но по отчёту, мной не перепроверялась.
3. **Низкая.** Vite предупреждает, что `vitest.config.ts` читается как ESM без `"type": "module"` в `package.json`. Это не ошибка, но шум. Решение: переименовать в `vitest.config.mts` или добавить `"type": "module"`, проверив совместимость с Next.
4. **Низкая.** `status.md` не обновлён: там по-прежнему «план одобрен», хотя AGENTS.md требует обновлять его после каждого заметного шага.
5. **Низкая.** Prisma закреплена на v6 (`^6.19.3`), это осознанный выбор, но в плане он не отражён. Нужно записать причину. Версии остальных зависимостей (Next 16, TypeScript 7, Vitest 5) новые. Их совместимость подтверждается только тем, что сборка проходит.
6. **Низкая.** Схема не отформатирована (`prisma format`): выравнивание полей в `Family`, `MealLog` и `PointsEvent` неровное. В планируемой модели нет индекса по `User.email`, но он уже `@unique`. Поля `type`, `mealType`, `mood` и `metric` заданы как строка или число без ограничений. Валидацию нужно предусмотреть на этапах 3 и 5.
7. **Информационно.** Auth.js и bcrypt ещё не установлены. Это соответствует плану: они нужны на этапе 2. Тесты этапа 1 проверяют только статику (схему, `.env.example`, `package.json`) и не ловят ошибок сборки. Исключение: `nextConfig`, и тот пустой.

4. Обновить `status.md`: этап 1 завершён, дальше этап 2.
